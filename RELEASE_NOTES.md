## 0.3.9 — VLESS снова работает (корень — на сервере)

> ⚠️ **0.3.7 и 0.3.8 битые — не используйте.** `versionName` в `pubspec.yaml`
> не совпадал с тегом релиза (остался `0.3.7`), из-за чего автообновление
> зацикливалось: апдейтер сравнивает тег релиза с версией установленного APK, а
> APK внутри рапортовал старую версию → «обновись» повторялось бесконечно. В
> 0.3.9 `pubspec.yaml` поднят до `0.3.9+24` — тег и versionName совпадают, цикл
> разорван. Битые теги/релизы v0.3.7 и v0.3.8 удалены.

**Симптом:** VPN подключается, но интернета нет; `warmup HTTP 503`. На сервере в
логе xray — `REALITY: server name mismatch: www` / `handshake did not complete`.

**Корневая причина — сервер, не клиент:** REALITY-цель `www.microsoft.com`
включила постквантовый TLS (X25519MLKEM768). REALITY «крадёт» TLS-хендшейк цели
— с PQ-ключами кража не завершается, инбаунд отвергает всех клиентов. Доказано
loopback'ом xray↔xray: microsoft → fail, `www.apple.com` → HTTP 200. **Фикс на
сервере:** REALITY-цель 443/2087 сменена на `www.apple.com` (x-ui БД + restart).
Ссылки надо перевыпустить с `sni=www.apple.com` (старые с microsoft мертвы).

**Что исправлено в клиенте (`SingBoxConfig.kt`):**
- **uTLS теперь всегда включён** с `fp=chrome` по умолчанию. Без uTLS REALITY
  отвергает ClientHello, поэтому ссылка без `fp=` раньше собирала мёртвый тоннель
  (паритет с десктопным `parser.rs`). Добавлены xtls/alpn/insecure и ws-Host.
- **Вычистка всех пробелов из ссылок.** Автокоррекция мобильной клавиатуры
  (Gboard) вставляла пробелы (`www. Apple. com`), тихо ломая SNI/pbk.

Переключение по сети (WiFi→hysteria2 «w», Mobile→VLESS «m») уже работало — не менялось.

## 0.3.1 — Fix мобильного интернета

**Два бага, из-за которых не работал 4G/5G:**

1. **Bandwidth cap обходился URL-параметрами** — 3X-UI часто генерирует ссылки с `?up=N&down=N`. parseHysteria2 записывал эти значения в конфиг, и проверка `if (!has("up_mbps"))` пропускала их, обходя ограничение 10 Mbps. Без ограничения hysteria2 использует BBR-режим с агрессивным burst → DPI мобильного оператора дропает QUIC-сессию до установки тоннеля.

2. **Нет прогрева прокси** — sing-box устанавливает hysteria2 лениво, только при первом трафике. На 4G с ~130ms RTT handshake занимает 300-500ms. DNS-запросы в браузере могут истечь до того, как тоннель готов, и браузер показывает "нет соединения" навсегда.

**Что исправлено:**
- Bandwidth cap 10 Mbps всегда применяется на 4G/5G, даже если в ссылке есть `?up=N&down=N`
- После старта VPN и после смены WiFi↔Мобильный — автоматический прогрев через Clash API (`/proxies/proxy/delay`), который форсирует установку hysteria2-тоннеля до прихода пользовательского трафика
